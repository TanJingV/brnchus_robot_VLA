# D435 TDCR 三维关键点采集

## 直接运行

双击项目根目录的 `run_d435_capture.bat`，或在 Bronchoscope 环境中运行：

```powershell
python -m Visual_information.d435_tdcr_capture
```

启动后，正常实验不需要再输入其他命令。右侧可滚动控制栏已经提供：

- 两种三维测量模式切换；
- 实时D435、RealSense Bag和模拟源切换；
- 普通RGB侧相机实时检测、设备名称下拉选择与热切换；
- 内窥镜摄像头独立检测、预览、缩放和录像；
- Trio地址连接、断开和零输入；
- MuJoCo启停与XML选择；
- D435/侧相机内外参采集、求解和加载；
- session输出目录、开始/停止记录；
- D435 RGB与侧相机RGB同步视频采集；
- 配置加载/保存；
- session选择和离线参数辨识。

后文命令行参数只作为自动化、批处理和无界面调试的备用入口。

主工作区采用三面板布局：左侧D435多流监视器以2×2子画面同步显示RGB关键点、彩色深度信息图、左IR和右IR；右上显示普通RGB侧相机，右下显示真实关键点与MuJoCo预测的三维形状。MuJoCo实时同步默认关闭，此时不会创建bridge、推进仿真或计算同步误差；只有在界面中主动勾选后才加载XML并开始计算。

“关键点感知”中的总开关可独立关闭7点捕捉。关闭后仍采集、预览并可记录RGB、Depth、左右IR和侧相机原始流，但不会执行颜色分割、双目匹配、三角化、卡尔曼更新或关键点误差计算；数据中会明确写入 `tracking_disabled`，不会伪造三维坐标。

颜色带识别采用HSV候选分割、Lab色度距离、饱和度加权亚像素中心、时间连续性和重复目标抑制联合评分。K0–K6始终由各自颜色原型固定身份，不按屏幕位置重新编号；同色背景或反光目标若远离上一帧位置，不会仅因面积较大而抢占身份。颜色原型会以很小步长在线适应曝光变化。首次实验或更换贴纸/光照后，应让7条颜色带同时清晰可见并点击“用当前帧校准7条颜色带”；双视图模式会为D435和侧相机分别建立颜色原型。叠加标签中的 `C` 是纯颜色识别置信度，`3D` 是叠加IR/Depth质量后的最终置信度。

关键点深度不是直接读取彩色图某一个像素。程序先在RGB中定位彩色环，以局部Depth中值获得搜索初值；再在左IR中细化中心，在右IR的同一极线附近用归一化互相关匹配相同纹理，并通过抛物线拟合得到亚像素视差。最终采用 `Z = fx * baseline / disparity` 计算关键点深度，原始Depth只用于一致性校验和双目失效时的低置信度回退。UI左右IR画面会叠加K0–K6匹配点，右IR同时显示视差值。深度信息图只对预览应用空间中值、孤立点抑制和低延迟时域滤波；记录与关键点算法仍保留原始Depth，避免显示滤波污染实验数据。

深度子窗右上角可在“深度”和“IR点云”间实时切换。IR点云使用D435内部左右红外立体匹配输出的Depth，按当前对齐后的相机内参反投影为三维坐标，并使用同步RGB图像着色；显示端进行下采样和去噪以维持实时帧率，不修改保存的原始深度或左右IR图像。

深度与3D预览默认启用边缘保护的稳定填洞：只补全邻域深度一致的小孔，并可在邻域仍匹配时保留最多3帧的上一有效深度；物体轮廓两侧深度差过大时不会跨边缘填充。3D渲染使用独立的低分辨率时域状态和3×3表面铺点，减少点云内部不断闪烁的黑孔。相关开关位于相机参数栏的“Depth Range & Point Cloud”，这些处理只影响显示和3D预览，不修改原始Z16视频、关键点深度或导出的实验测量数据。

“三维点详细信息”区域实时列出K0–K6的基座XYZ、深度标准差、置信度和MuJoCo误差。点击表格行可查看原始/滤波相机坐标、RGB及左右IR像素、视差、完整三维标准差、侧视重投影和仿真坐标。RGB、Depth、左右IR和IR点云均可直接点击查询附近有效点的左IR相机坐标、基座坐标、估计不确定度和时间戳；侧相机仅在点击已经建立三维对应的关键点时返回坐标，不为普通单目背景像素伪造深度。“导出当前稠密点云”同时生成基座坐标二进制PLY和包含相机/基座坐标、RGB及源像素的NPZ。

D435主RGB、深度/IR点云、左IR、右IR和侧面RGB视图均支持鼠标滚轮进行1×–8×放大，按住左键拖动查看局部区域，双击画面或点击标题栏的倍率按钮恢复1×。“D435四视图联动缩放”默认开启，在任意D435子窗进行缩放、拖动或复位时，其余三个D435画面会使用相同倍率和归一化视窗中心同步变化。侧相机RGB始终单独控制，不跟随D435视图；关闭联动后四个D435画面也可分别检查。缩放不会裁剪或修改保存的原始图像，但会定义当前在线关键点处理ROI。

关键点处理会实时跟随当前视窗ROI：D435检测ROI取自主RGB当前的缩放倍率和拖动中心；侧相机检测ROI取自侧RGB自己的独立视窗。检测始终在原始分辨率图像的ROI内执行，结果再以全图像素坐标进行IR匹配、深度反投影和三维计算，因此放大不会改变几何尺度。ROI之外的标记不会作为当前帧有效测量，短时仅按既有预测超时规则显示为预测点。RGB和侧RGB叠加图中的黄色边框标明实际参与处理的ROI。每帧两路归一化ROI均写入 `samples.csv` 和 `keypoints.npz`。

记录区的“同步保存D435 RGB＋侧相机RGB视频”默认开启。每个session额外生成 `d435_rgb.mp4`、`side_rgb_synchronized.mp4`、`synchronized_rgb.mp4` 和 `video_timestamps.csv`。D435曝光时刻作为视频主时钟，侧相机按最近采集时刻配对；时间表保存两路帧号、主机单调时钟和毫秒级偏差。侧帧临时缺失时写入明确的占位帧并标记 `side_valid=0`，从而保证三个视频的帧索引始终一致。

## 内窥镜独立预览与统一记录

主工作区的“内窥镜 RGB”窗口由单独的取帧线程驱动，不依赖D435是否启动，也不与模式1的侧面RGB相机共用设备。右侧“内窥镜摄像头”栏会实时列出非RealSense摄像头；当前设备优先选择 `HD WebCam`，也可以从下拉栏改选。内窥镜窗口支持独立滚轮缩放、拖动和倍率复位。

设备连接和预览彼此独立，记录操作则统一管理：点击“开始采集/开始记录”后，勾选的D435窗口、内窥镜、NDI/EM和七轴电机数据进入同一个session；点击“停止采集/停止记录”时全部停止写入并分别完成文件校验，但不会断开任何设备。记录期间若直接点击“停止相机”，程序会要求先完整结束本次session，避免只关闭D435造成多路数据长度不一致。

勾选“记录内窥镜视频和时间戳”后，session中新增：

- `endoscope_rgb.mp4`：使用摄像头实际输出分辨率和实际标称帧率保存，不强制拉伸；
- `endoscope_timestamps.csv`：逐帧保存视频索引、源帧号、采集单调时钟和到达时钟；
- `endoscope_summary.json`：保存设备信息、提交/编码/解码帧数、丢帧、帧率、编码器和校验状态。

停止记录后，只有所有已勾选数据流均完成写入且视频可重新打开、编码帧数与解码帧数一致时，才会弹出“记录成功”提示；任何一路缺失或校验失败都会保留异常信息而不会误报成功。

`samples.csv`与`keypoints.npz`还会保存每点完整协方差、预测状态、RGB/左右IR像素、IR视差和定位来源，能够离线复核UI中显示的每个三维结果。

> D435 必须使用支持 SuperSpeed 数据的 USB 3.x 线缆并直连电脑的蓝色或 `SS` 标识端口。程序启动时会检查协商速率；若设备仍显示 USB 2.1，会在界面中给出明确提示并停止启动，避免以“无帧”状态继续实验。PSE0520 侧相机默认采用实测低延迟配置 640×480@30 Hz。

没有相机时验证完整算法链：

```powershell
python -m Visual_information.d435_tdcr_capture --synthetic
```

界面顶部可以实时切换两种三维测量模式：

- `模式1：D435＋侧面RGB双视图融合`：D435三维结果经侧视重投影校验，Depth异常时使用两路RGB三角化。
- `模式2：D435双目＋Depth内部融合`：使用D435 RGB、左右IR和Depth，不启动侧相机。

侧相机下拉栏每3秒读取一次系统设备列表，并保留“刷新设备”按钮。列表会显示设备名称和实际OpenCV Index，同时自动排除由RealSense管线独立管理的D435；实验中只需从下拉栏选择目标普通RGB相机，不再手动猜测Index。记录期间为保护session一致性，不允许切换侧相机。

直接以双视图模拟模式启动：

```powershell
python -m Visual_information.d435_tdcr_capture --synthetic --mode dual_view
```

使用真实侧相机Index 1和已经完成的联合标定：

```powershell
python -m Visual_information.d435_tdcr_capture --mode dual_view --side-camera-index 1 --side-calibration .\side_camera_calibration.json
```

读取真实七轴时使用：

```powershell
python -m Visual_information.d435_tdcr_capture --trio PCMCAT
```

也可以从原主界面“控制”页点击“打开 D435 采集与MuJoCo对齐”。该入口复用主界面已经建立的Trio连接和MuJoCo实例，不会重复连接控制器。

## NDI Aurora EM同步采集

右侧“NDI Aurora 电磁跟踪”区域会实时扫描串口。连接SCU后选择显示为
`NDI Aurora SCU Port`的端口，确认传感器对应的 `.rom` 文件，然后点击“连接NDI”。
界面会显示原生更新率、有效工具数量和Handle编号；当前设备默认以Handle 10作为主工具，
也可选择“自动”或手动修改。

NDI串口驱动运行在独立进程中，与D435取帧、视频编码和Qt界面不共享Python GIL；
主程序只接收最多四帧的低延迟位姿队列，因此NDI积压不会拖慢相机预览。

勾选“随电机采样同步保存 EM CSV”后，两种工作模式都会在session中生成：

- `em_data_100hz.csv`：每个有效电机采样恰好一行，保存主Handle的位置、四元数、4×4矩阵、质量、原始NDI帧号和全部工具JSON；
- `em_summary.json`：保存实际电机采样率、NDI原生帧率、复用帧数、数据年龄、丢行和异常统计。

Aurora与电机频率不必相同。程序不会把重复的EM数据伪装成新测量：
`new_em_frame=1`表示该电机时刻取得了新的NDI帧，`em_age_ms`表示最近EM帧相对电机时刻的年龄。
因此CSV行频率严格跟随电机，同时仍保留Aurora真实硬件时序。

## 参数辨识

```powershell
python -m Visual_information.d435_tdcr_capture.identify --session .\d435_sessions\session_YYYYMMDD_HHMMSS_xxxxxx
```

输出 `identified_profile.json` 和 `identification_report.md`，不会覆盖基础XML。

完整的硬件布置、标定方法、数据字段和验收流程见
[`docs/d435_tdcr_capture.md`](../docs/d435_tdcr_capture.md)。
